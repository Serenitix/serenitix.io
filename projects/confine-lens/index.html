Confine Lens

Quantify Attacker Capability, Not Just Removed Functionality

Serenitix · Contact us about this listing

The problem

Container hardening tools reduce things: packages, files, image size, functions, syscalls, policy permissions. Those reductions are useful engineering signals. They do not answer the operational security question: what attacker capability remains after hardening?

Current practice relies on reduction counts, manual review, or isolated policy analysis. A report that a policy blocked a number of syscalls says little about whether exploit-relevant authority went away. One policy can remove many low-impact syscalls and leave a few high-authority interfaces; another can remove fewer syscalls and eliminate process-control or network authority. Counting cannot tell them apart.

The approach

Confine Lens evaluates confinement by the capability it removes from the attacker. The model separates a local unit from the end-to-end outcome:

  • Interface authority is the local unit: the authority represented by a syscall or system interface that attacker-controlled data can reach.
  • Attacker capability is the end-to-end outcome: the transitive closure of attacker-tainted paths, the syscall interfaces those taints reach, and the interface authority those syscalls convey.

Confine Lens compares an unconfined baseline against a confined or hardened version of the same container. It identifies attacker-facing interfaces, traces attacker-controlled influence, resolves reachable syscall authority, and aggregates the resulting attacker capability. The output is a before/after report: which authority confinement revoked, what capability remains, and which interfaces drive the remaining risk. Instead of "this policy removed 70 percent of syscalls," the report says which attacker authority changed.

Confine Lens complements debloating, minimal images, syscall policies, and verification tools. It measures the security consequence of their output.

What exists today

  • An LLVM-pass taint analysis that follows data from annotated sources to syscall sinks, with Confine Lens examples built against it.
  • An early prototype that scores Confine-generated seccomp policies per binary in a container image.
  • An existing tool that scores at kernel level. It needs modest modification for this use.
  • The Confine Lens architecture, figures, and a prototype authority-delta demonstration.
  • The interface-analysis and privilege-analysis research behind it (see Related work).

What an award delivers

Planned work, not yet built:

  • Re-basing the analysis on Hyperplanes, Serenitix's analysis foundation: DUC def-use influence analysis and a program capability graph.
  • Policy-to-authority delta reporting: given a baseline and a confinement policy, report what interface authority remains.
  • Interface exposure and memory dereference path analysis: which paths are attacker-influenced, guarded or unguarded, and connected to dangerous operations.
  • An operational tool: repeatable scoring, dashboards, CI/CD integration, and policy comparison for deployment decisions.

Related work

Confine Lens builds on published research by Serenitix founder Nathan Dautenhahn. CIVScope (KISV 2023) provides the foundation for interface vulnerability and guarded-path analysis. The Object-Encapsulation Model (LangSec 2023), a whole-program privilege and compartmentalization analysis, informs the privilege and syscall-sensitivity framing. For a related Serenitix listing on authority regressions in CI/CD, see the SURE paper page.

Team

  • Nathan Dautenhahn, lead: operating-system security, privilege decomposition, LLVM-based analysis, compartment interfaces, and influence reasoning.
  • Sergey Bratus: LangSec, weird machines, binary semantics, and exploitation-relevant reasoning about authority boundaries.
